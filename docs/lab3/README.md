Почему доступных адресов не 256? В подсети /24 всего 256 адресов, но AWS забирает себе 5 из них, поэтому остается 256 минус 5, то есть 251.

Какие адреса подсети 10.0.0.0/24 занимает AWS и для чего? Адрес 10.0.0.0 это адрес сети. Адрес 10.0.0.1 занят виртуальным маршрутизатором VPC. Адрес 10.0.0.2 это DNS-сервер VPC. Адрес 10.0.0.3 зарезервирован на будущее. Адрес 10.0.0.255 это широковещательный адрес, в VPC он не работает, но все равно закрыт.

Сколько еще подсетей /24 поместится в VPC? В /16 помещается 256 подсетей /24. Четыре уже созданы, значит можно создать еще 252.

Это не адрес db-server, потому что NAT заменяет приватный адрес сервера своим публичным адресом, а у самого сервера публичного адреса нет.

Что делает каждый из трех механизмов ограничения доступа к базе? Что произойдет, если ошибиться только в одном? Почему PostgreSQL продолжает работать после удаления NAT Gateway? Что придется сделать, когда понадобится установить обновления безопасности? NAT нужен только для выхода в интернет, а веб-сервер подключается к базе внутри VPC по локальному маршруту. Для обновлений безопасности придется снова создать временный NAT Gateway и маршрут, поставить обновления и удалить все обратно.

---
![Подтверждение выполнения](img/9.png)

Скрин 1. Показывает работающую страницу приложения TimeCapsule, открытую по Elastic IP сервера timecapsule-dev-app.

Почему Elastic IP нужен app-server, но не нужен bastion? Пользователи заходят на app-server по одному адресу, поэтому адрес не должен меняться после остановки и запуска сервера. Bastion нужен только мне для SSH, и я просто обновляю его адрес в файле config.

Сколько стоит Elastic IP, пока сервер остановлен, и почему? Около 0,005 доллара в час, это примерно 3,6 доллара в месяц. AWS берет плату за выделенный публичный адрес, пока он существует, даже если сервер остановлен.

Понадобится ли Elastic IP, когда перед сервером появится балансировщик нагрузки? Нет, не понадобится. Пользователи будут заходить на DNS-имя балансировщика, и Elastic IP на app-server можно освободить.

Зачем для базы в отдельной сети нужен новый сильный пароль, если порт 5432 и так закрыт Security Group? Security Group это только один слой защиты. Если ее настроят неправильно или взломают веб-сервер, пароль остается последним барьером. Старый пароль из ЛР2 к тому же уже мог где то светиться.

### Вопросы для устной защиты
---

- Как проходит запрос пользователя от браузера до базы данных? Какие маршруты и правила фильтрации он проходит? Браузер идет на Elastic IP сервера app-server. Пакет попадает в Internet Gateway, по таблице public-rt уходит в подсеть public-a, проходит Network ACL и Security Group web-sg, которая разрешает порт 80. Приложение берет адрес базы по имени db.timecapsule.internal и идет на db-server по локальному маршруту. Там пакет проходит Network ACL и db-sg, которая разрешает порт 5432 только от web-sg, а потом pg_hba.conf и проверку пароля.

- Злоумышленник знает приватный IP db-server. Что ему нужно, чтобы подключиться к базе? Из интернета маршрута к db-server нет, поэтому ему сначала нужно попасть внутрь VPC на сервер из группы web-sg. Потом ему нужны правильные имя пользователя, имя базы и пароль, а подключение должно идти с адреса подсети public-a, иначе pg_hba.conf его отклонит.

- Чем временный NAT Gateway лучше постоянного и какие неудобства он создает? Он оплачивается только за часы работы, а постоянный стоил бы около 1,25 доллара в сутки. Неудобство в том, что его каждый раз нужно создавать и удалять руками, ждать несколько минут, добавлять и убирать маршрут, подписывать Elastic IP и не забыть все удалить.

- Как изменится схема, если приложение должно пережить отказ зоны eu-central-1a? Сейчас и app-server, и db-server стоят в зоне 1a. Не хватает второго сервера приложения в зоне 1b, реплики базы в подсети private-b, балансировщика нагрузки между двумя зонами и автоматического переключения на реплику.
