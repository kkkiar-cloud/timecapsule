# ADR-0002. Размещение базы данных

* Статус: принято
* Дата: 2026-10-17

Контекст : в ЛР2 приложение и база были на одном сервере в default VPC, там все подсети публичные. В ЛР3 приложение переехало в свою сеть timecapsule-dev-vpc. Надо было решить, где держать базу. К ней не должно быть доступа из интернета, подключаться должен только сервер приложения и чтобы это было недорого.

Решение : база стоит на отдельном сервере timecapsule-dev-db в приватной подсети timecapsule-dev-private-a, публичного IP у неё нет. Приложение подключается по имени db.timecapsule.internal (приватная зона Route 53). Порт 5432 открыт только для web-sg, SSH только через bastion.

Рассмотренные альтернативы :
* Всё на одном сервере, как в ЛР2: проще и дешевле, но база в публичной подсети, и если взломают приложение, данные тоже доступны. Масштабировать можно только всё вместе.
* Отдельный сервер в публичной подсети: база отделена от приложения, и обновления можно ставить без NAT. Но у сервера есть публичный IP и маршрут в Internet Gateway, и одна ошибка в Security Group откроет порт 5432 в интернет.

Последствия :
* Плюсы: из интернета к базе не подключиться, т.к. нет публичного IP, нет маршрута, порт закрыт. Если ошибиться в одном месте, остальные всё равно защищают. Если db-server пересоздать с другим адресом, надо поменять только запись db в зоне, в .env ничего менять не надо.
* Обновления: постоянного выхода в интернет у базы нет. Когда нужно поставить обновления, я создаю временный NAT Gateway в public-a, добавляю маршрут 0.0.0.0/0 в private-rt, делаю sudo dnf -y update и сразу удаляю маршрут, шлюз и Elastic IP. NAT стоит около $1,25 в сутки, если про него забыть, а за час работы это центы. Постоянный NAT обошёлся бы в десятки долларов в месяц. Минус в том, что обновления приходится делать вручную.
* Elastic IP у app-server нужен, чтобы адрес сайта не менялся после остановки и запуска сервера. Он стоит около $0,005 в час всегда, даже когда сервер остановлен. Когда перед сервером появится балансировщик нагрузки, пользователи будут ходить на него, и Elastic IP будет не нужен, его можно освободить.
* Минусы: база только на одном сервере в одной зоне eu-central-1a, если зона упадёт, не будет ни базы, ни приложения. Файлы пользователей лежат на диске app-server и пропадут, если его удалить. Настраивать сложнее, чем в ЛР2: нужны bastion, приватная зона и временный NAT.
